# v0.1.6 reference review

This pass studies public Blender MCP implementations for architectural ideas, then re-implements only the parts that fit 1782-92's three-tool and token-budget philosophy.

Reviewed projects:

- `ahujasid/blender-mcp`
- `glonorce/Blender_mcp`
- `6xvl/blender-mcp`
- `minihellboy/claude-blender`

Adopted ideas, re-designed for 1782-92:

- a health/version probe, but folded into `inspect("status")` and served outside the Blender main-thread queue so it still answers while a long job is busy;
- compact hierarchy/search/spatial scene comprehension via `inspect("tree")`, `inspect("find:TERM")`, and `inspect("oN:spatial")` instead of dozens of extra MCP tools;
- current 3D-editor capture via `render({mode:"viewport"})`, while keeping deterministic `fast/lookdev/wire` renders for ordinary iteration;
- stronger runtime observability without changing the three public tools.

Ideas deliberately not copied:

- hundreds of direct-dispatch tools: useful for discoverability, but contrary to this project's context-budget target;
- unrestricted Python execution: 1782-92 keeps its guarded AST policy and cooperative execution budget;
- forced network auto-update: development linking and explicit version mismatch detection are safer and deterministic;
- external asset and text/image-to-3D services: out of scope for the minimal local control plane.

The goal is not feature parity. It is to absorb proven workflow ideas while keeping `inspect / apply / render` as the whole model-visible surface.
